Windows Terminal, with more in it

A personal fork of Microsoft's Windows Terminal. Same core, plus a running production/test deploy system, a local automation pipe upstream refused twice, and a pile of quieter fixes to how links, icons and windows behave.

Automation

Local control pipe

A named pipe per Terminal process (\\.\pipe\wt-control-<pid>) that lets another process list panes, capture a specific pane's text, or send it input — precisely, not via UI Automation and SendKeys. Security-scoped to the current user, with a settings kill switch. Upstream has refused this exact capability twice (issue #9368, PR #20106); their own automation surface doesn't reach from WSL.

Deploy system

Live production / disposable test slots

Two parallel installs, wtt and wtd, with distinct single-instance identities so both can run at once. Production changes only on an explicit promote — never a side effect of a build — with a tab-row badge, an update-available banner, and an About dialog naming exactly which commit and build time you're running.

Deploy system

CI-built, self-updating

Builds happen in CI, not on the machine running Terminal — a background poller fetches the newest green build on a configurable interval (its own Settings UI control) and stages it for the next promote, no manual fetch required.

Links

Plain-click URLs, everywhere

Links open on a plain click — no Ctrl required, toggleable in Settings — and work correctly inside mouse-mode apps like tmux, where a click would otherwise just move the cursor.

Links

A link card that actually fits

The plain hover tooltip was replaced with a richer card — configurable delay, a "how to open" hint, room for an action button — that flips to whichever side actually has room and never renders past the edge of the pane, on either axis.

Links

Slack-style and WSL links

<url|label> bracketed links (the format Slack and many CLIs emit) become clickable with the label shown, and a WSL file:// link resolves to the right distro's UNC path — including fragments — so it actually opens the file it points at.

UI & theming

Separate light/dark color schemes

Pick one scheme for light mode and a different one for dark mode, right in the Settings UI — the terminal actually follows the OS appearance instead of being stuck on whichever scheme you set last.

UI & theming

Icons that don't block on the network

A profile's http(s) icon is cached locally, so settings load never stalls waiting on a remote image — and glyph/emoji profile icons get rasterized into real jump-list icons instead of showing a blank tile.

UI & theming

Quieter defaults

Text selection can search with your default engine, the mouse wheel no longer changes font size or opacity by accident, window position and size are remembered per window, and quitting doesn't ask "close all windows?" when there's only one open.
